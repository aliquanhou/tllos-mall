# 消息管理

## 1. 页面概述
### 功能描述
消息管理页面，支持管理商城公告、系统消息、推送通知，包括消息模板、发送记录、阅读统计。消息管理是商城与用户沟通的重要渠道。

### 核心指标
| 指标 | 含义 | 业务价值 |
|------|------|----------|
| 消息总数 | 所有消息数量 | 衡量消息规模 |
| 已发送 | 已发送的消息数 | 衡量触达量 |
| 阅读率 | 消息阅读比例 | 衡量消息效果 |
| 今日发送 | 今日发送消息数 | 衡量近期活跃度 |

### 使用场景
1. 公告管理：发布和管理商城公告
2. 消息模板：配置消息模板
3. 推送管理：向用户推送消息
4. 发送记录：查看消息发送和阅读情况

## 2. API接口清单（基于真实控制器实现）
| 方法 | 路径 | 控制器方法 | 说明 | 权限标识 |
|------|------|-----------|------|----------|
| GET | /api/v1/admin/notices | AdminNoticeController@index | 消息列表 | notice:list |
| POST | /api/v1/admin/notices | AdminNoticeController@store | 新增消息 | notice:create |
| GET | /api/v1/admin/notices/{id} | AdminNoticeController@show | 消息详情 | notice:view |
| PUT | /api/v1/admin/notices/{id} | AdminNoticeController@update | 编辑消息 | notice:edit |
| DELETE | /api/v1/admin/notices/{id} | AdminNoticeController@destroy | 删除消息 | notice:delete |

### 请求参数
| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| page | int | 否 | 页码默认1 |
| limit | int | 否 | 每页数量默认20 |
| keyword | string | 否 | 搜索关键词 |
| type | int | 否 | 类型 |
| status | int | 否 | 状态 |
| start_date | date | 否 | 开始日期 |

### 返回示例
```json
{
  "code":0,
  "data":{"total":34,"page":1,"list":[
    {"id":1,"title":"9月促销活动通知","type":1,"type_text":"系统公告","content":"9月1日-9月30日，全场满减活动...","target_type":1,"target_text":"全体用户","send_count":12345,"read_count":8900,"status":1,"status_text":"已发送","send_time":"2026-09-01 10:00:00","created_at":"2026-08-25"}
  ]}
}
```

| 错误码 | 说明 |
|--------|------|

## 4. 操作流程
```
创建消息 → 填写标题/类型/内容/目标用户
├── 保存草稿 → 状态为草稿
├── 立即发送 → 状态为已发送 → 推送给目标用户
│   ├── 用户阅读 → 阅读数+1
│   └── 用户未读 → 消息保留在未读列表
├── 定时发送 → 到指定时间自动发送
├── 撤回消息 → 状态为已撤回（用户端不再显示）
└── 删除消息 → 草稿状态可删除
```

### 数据刷新机制
1. 页面加载加载消息列表
2. 增删改后刷新列表
3. 阅读数准实时更新

## 8. 常见问题
| 问题 | 原因 | 解决方案 |
|------|------|----------|
| 列表数据为空 | 数据库无数据或筛选条件不对 | 检查筛选条件确认有测试数据 |
| 新增保存失败 | 必填字段未填或格式错误 | 检查表单校验查看错误提示 |
| 编辑回显不全 | 接口返回字段缺失 | 检查控制器返回字段 |
| 删除后仍显示 | 缓存未清除 | 清除缓存 |
| 用户收不到消息 | 推送配置错误或用户关闭通知 | 检查推送配置和用户通知设置 |
| 阅读数不更新 | 统计延迟或缓存 | 清除缓存等待统计更新 |
