# 售后管理

## 1. 页面概述
### 功能描述
售后管理页面，支持查看用户售后申请、审核售后、处理退货退款。售后管理是维护用户权益和商城口碑的重要功能。

### 核心指标
| 指标 | 含义 | 业务价值 |
|------|------|----------|
| 售后总数 | 所有售后申请数 | 衡量售后量 |
| 待审核 | 待审核售后数 | 及时处理提醒 |
| 已完成 | 已完成售后数 | 衡量处理效率 |
| 退款金额 | 累计退款金额 | 衡量售后成本 |

### 使用场景
1. 售后审核：审核用户退货退款申请
2. 退款处理：确认收货后退款
3. 售后查询：按状态/订单筛选
4. 售后统计：查看售后率和原因

## 2. API接口清单（基于真实控制器实现）
| 方法 | 路径 | 控制器方法 | 说明 | 权限标识 |
|------|------|-----------|------|----------|
| GET | /api/v1/admin/after-sales | AfterSaleController@index | 售后列表 | aftersale:list |
| GET | /api/v1/admin/after-sales/{id} | AfterSaleController@show | 售后详情 | aftersale:view |
| POST | /api/v1/admin/after-sales/{id}/audit | AfterSaleController@audit | 售后审核 | aftersale:audit |
| POST | /api/v1/admin/after-sales/{id}/refund | AfterSaleController@refund | 确认退款 | aftersale:refund |

### 请求参数
| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| page | int | 否 | 页码默认1 |
| limit | int | 否 | 每页数量默认20 |
| keyword | string | 否 | 搜索关键词 |
| order_no | string | 否 | 订单号 |
| status | int | 否 | 售后状态 |
| type | int | 否 | 售后类型 |

### 返回示例
```json
{
  "code":0,
  "data":{"total":56,"page":1,"list":[
    {"id":1,"order_no":"TLL202609010001","user_id":1,"user_name":"张三","type":1,"type_text":"退货退款","status":0,"status_text":"待审核","reason":"商品质量问题","amount":"5199.00","created_at":"2026-09-01 12:00:00"}
  ]}
}
```

### 错误码
| 错误码 | 说明 |
|--------|------|
| 10001 | 无权限操作 |
| 10002 | 数据不存在或已删除 |
| 10003 | 参数校验失败 |
| 10004 | 数据库操作失败 |
| 10005 | 售后状态不允许此操作 |
| 10006 | 退款失败请检查支付渠道 |

## 4. 操作流程
```
用户申请售后 → 待审核状态
├── 管理员审核通过 → 待用户退货
│   ├── 用户寄回商品 → 待收货
│   │   └── 管理员确认收货 → 退款中 → 已完成
│   └── 用户取消 → 已取消
└── 管理员审核拒绝 → 已拒绝（通知用户）
```

### 数据刷新机制
1. 页面加载加载售后列表
2. 审核/退款后刷新状态
3. 新售后实时进入待审核

## 8. 常见问题
| 问题 | 原因 | 解决方案 |
|------|------|----------|
| 列表数据为空 | 数据库无数据或筛选条件不对 | 检查筛选条件确认有测试数据 |
| 新增保存失败 | 必填字段未填或格式错误 | 检查表单校验查看错误提示 |
| 编辑回显不全 | 接口返回字段缺失 | 检查控制器返回字段 |
| 删除后仍显示 | 缓存未清除 | 清除缓存 |
| 退款失败 | 支付渠道配置错误或余额不足 | 检查支付配置和账户余额 |
| 售后状态不更新 | 事务未提交或缓存 | 清除缓存检查数据库 |
