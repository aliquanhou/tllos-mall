# 分销设置

## 1. 页面概述
分销设置是分销体系的全局配置中心，采用**键值对配置模式**，管理分销功能的开关、自购佣金、最低提现金额、结算周期等核心参数。管理员可在此页面查看和修改所有分销相关配置，配置实时生效。

### 配置模式说明
- **存储方式**：键值对（key-value），每条配置独立存储
- **读取方式**：一次性读取所有配置，以对象形式返回前端
- **更新方式**：前端提交完整配置对象，后端遍历更新每个配置项
- **无分页/无列表/无删除**：配置项是固定的，不存在增删概念

### 配置项清单
| 配置键 | 类型 | 默认值 | 当前值 | 说明 |
|--------|------|--------|--------|------|
| is_open | boolean | 1 | 1 | 分销功能总开关（1开启0关闭） |
| self_buy_commission | boolean | 1 | 1 | 自购佣金开关（1允许分销商自购获得佣金0不允许） |
| min_withdraw | decimal | 10.00 | 10.00 | 最低提现金额（元） |
| settlement_days | int | 7 | 7 | 佣金结算周期（天，订单完成后N天可提现） |

### 使用场景
1. 功能开关：开启/关闭整个分销功能
2. 佣金规则：配置是否允许分销商自购获得佣金
3. 提现规则：配置最低提现金额，防止小额提现
4. 结算周期：配置佣金结算天数，控制资金风险

## 2. API接口清单

| 方法 | 路径 | 控制器方法 | 说明 |
|------|------|-----------|------|
| GET | /api/v1/admin/distribute/settings | DistributeController@getSettings | 获取所有分销配置（键值对对象） |
| POST | /api/v1/admin/distribute/settings | DistributeController@saveSettings | 更新分销配置（提交完整配置对象） |

## 3. 请求参数

### 获取分销配置
无请求参数。

### 更新分销配置
请求体为配置对象，每个键值对对应一个配置项：

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| is_open | string | 是 | 分销功能总开关（"1"开启/"0"关闭） |
| self_buy_commission | string | 是 | 自购佣金开关（"1"允许/"0"不允许） |
| min_withdraw | string | 是 | 最低提现金额（如"10.00"） |
| settlement_days | string | 是 | 结算周期天数（如"7"） |

**注意**：
- 所有配置值以字符串形式传输
- 提交时应包含所有配置项（完整对象），未提交的配置项不会被修改
- 支持数组类型配置值（自动json_encode存储）

## 5. 字段映射表

### distribute_settings表（5字段）
| 字段 | 类型 | 说明 |
|------|------|------|
| id | bigint | 主键 |
| key | varchar(100) | 配置键（唯一标识） |
| value | text | 配置值（字符串存储，数组自动json_encode） |
| created_at | timestamp | 创建时间 |
| updated_at | timestamp | 更新时间 |

### 配置项与业务逻辑映射
| 配置键 | 影响模块 | 业务逻辑 |
|--------|----------|----------|
| is_open | 全部分销功能 | 关闭时分销商无法推广商品，前端隐藏分销入口 |
| self_buy_commission | 分销订单佣金计算 | 开启时分销商自己购买商品也可获得佣金 |
| min_withdraw | 分销商提现 | 提现金额低于此值时拒绝提现申请 |
| settlement_days | 佣金结算 | 订单完成后N天，佣金从待结算转为可提现 |

## 6. 操作流程

### 分销配置读取与更新流程
```mermaid
flowchart LR
    A[管理员进入分销设置页面] --> B[前端调用GET /settings获取配置]
    B --> C[后端从distribute_settings表读取所有配置]
    C --> D[以key=>value对象形式返回前端]
    D --> E[前端渲染配置表单]
    E --> F[管理员修改配置项]
    F --> G[点击保存按钮]
    G --> H[前端调用POST /settings提交完整配置对象]
    H --> I[后端遍历配置项，updateOrInsert更新数据库]
    I --> J[返回保存成功]
    J --> K[配置实时生效]
```

### 配置生效机制
1. **实时生效**：配置保存后立即生效，无需重启服务
2. **读取时机**：各业务模块在需要时实时读取配置（非缓存）
3. **配置验证**：前端应做基本格式验证（数字范围、布尔值）
4. **配置备份**：建议修改前记录原始值，便于回滚

## 7. 权限控制
- 认证：Sanctum Token
- 中间件：auth:sanctum
- 当前权限模型：登录管理员可查看和修改分销设置
- 无细粒度权限点（permissions表不存在）
- 配置修改为写操作，需管理员权限

## 10. 常见问题
| 问题 | 原因 | 解决方案 |
|------|------|----------|
| 配置修改后不生效 | 前端缓存了旧配置 | 刷新页面或重新调用GET /settings获取最新配置 |
| 配置值类型错误 | 前端提交了数字类型而非字符串 | 所有配置值以字符串形式传输，如"1"而非1 |
| 部分配置未更新 | 提交时未包含所有配置项 | 提交完整配置对象，未提交的配置项不会被修改 |
| 分销功能关闭后分销商仍可推广 | 业务模块未读取is_open配置 | 检查各业务模块是否在操作前验证is_open配置 |
| 提现金额低于min_withdraw仍可提交 | 提现接口未验证最低金额 | 提现接口应读取min_withdraw配置并验证提现金额 |
| 佣金结算时间不正确 | 未使用settlement_days配置 | 结算逻辑应读取settlement_days计算佣金可提现时间 |
| 新增配置项不显示 | 前端硬编码了配置项列表 | 前端应动态渲染后端返回的配置项，或同步更新前端配置表单 |
